# AGENTS.md

Canonical guide for humans and AI agents working on Fetchr (display name `Fetchr`, app id `com.defo.fetchr`, Dart package `grabby`, org `com.defo`). The Dart package keeps its old name, so every import is `package:grabby/...`. Read it before changing code. `CLAUDE.md` only points here.

Generated options: Riverpod, go_router, Sentry, screen scaling, git hooks. On top of that Fetchr has a native Kotlin layer (yt-dlp, ffmpeg and aria2c through youtubedl-android) behind a pigeon contract. This guide covers only what this app has.

## Commands

Run `fvm flutter` and `fvm dart`. The SDK is pinned in `.fvmrc` and installed by fvm into `.fvm/` (gitignored); run `fvm install` once per clone. `tool/check.sh` puts `.fvm/flutter_sdk/bin` on `PATH` itself.

```bash
fvm flutter pub get
fvm flutter run
fvm flutter analyze
fvm flutter test                               # all
fvm flutter test test/modules/downloader/data/downloader_repository_impl_test.dart
fvm flutter test --name "substring of a test name"
fvm dart format lib test
fvm dart run build_runner build   # flutter_gen

fvm dart run pigeon --input pigeons/fetchr_api.dart   # regenerate the native contract, then format the Dart output
fvm dart format lib/core/platform/fetchr_api.g.dart
(cd android && ./gradlew :app:testDebugUnitTest)      # Kotlin unit tests (Windows: gradlew.bat)

bash tool/check.sh fast                        # import URIs, format and gates on staged files
bash tool/check.sh full                        # everything below
python tool/ci/arch_gates.py                   # architecture gates vs tool/ci/arch_baseline.json
python tool/ci/arch_gates.py --list            # status only, always exit 0
python tool/ci/arch_gates.py --update-baseline # lock in fixed violations (refuses while a total grew)
git config core.hooksPath tool/hooks           # once per clone: enable the tracked git hooks

fvm flutter build apk --debug --split-per-abi --target-platform android-arm64
fvm flutter build apk --release --split-per-abi --target-platform android-arm,android-arm64
```

Builds always pass `--split-per-abi --target-platform`: Gradle has no ABI config, and a fat APK carries libpython, ffmpeg and aria2c for every ABI. media_kit downloads libmpv at build time, so builds need network.

**ffmpeg on 16 KB page-size devices.** youtubedl-android 0.18.1's ffmpeg zip still carries 4 KB-aligned libwebp, so on a 16 KB page-size device every convert or merge fails. `patch<Variant>FfmpegZip` in `android/app/build.gradle.kts` rewrites that zip for arm64-v8a and x86_64 with the 16 KB-aligned libraries in `android/app/ffmpeg-16k/` (provenance in its README). When bumping youtubedl-android, check whether upstream fixed it and drop the override if so; when those libraries change, bump `FFMPEG_PKG_REV` in `YtDlp.kt`.

`tool/check.sh full` runs: gates self-test, gates, `dart format --set-exit-if-changed`, `build_runner`, a check that generated files are committed (skipped before the first commit), `flutter analyze`, `flutter test`. The tracked hooks in `tool/hooks/` run `fast` on pre-commit; pre-push runs `full` only with `FULL_CHECK=1 git push` (PowerShell: `$env:FULL_CHECK=1; git push`), otherwise run `bash tool/check.sh full` by hand before a release. The toolchain is pinned in `.fvmrc` (Flutter 3.47.9, Dart 3.13.7) and run through fvm; needs Python 3.9+ for the gates.

If the hooks do not fire on macOS or Linux, `chmod +x tool/check.sh tool/hooks/*`.

**Release signing.** `android/key.properties` (gitignored) with `storeFile`, `storePassword`, `keyAlias` and `keyPassword` signs release builds. Without it release builds fall back to the debug key so `fvm flutter run --release` works, but that APK is debug-signed and cannot update a release-signed install.

### CI/CD

Two GitHub Actions workflows in `.github/workflows/`. Both pin the Flutter version in their `FLUTTER_VERSION` env (keep it in step with `.fvmrc`) and call `flutter` directly (no fvm on the runner).

- **`ci.yml`** runs on every pull request, every push to `main` and on manual dispatch. It runs the checks of `tool/check.sh full` (import URIs, architecture gates, `dart format`, `flutter analyze`, `flutter test`) without fvm and without the build_runner diff check. On `main` and manual runs it also builds the release APKs, debug-signed and not uploaded, to catch breakage before a tag and to save the Gradle cache.
- **`release.yml`** runs when a `v*` tag is pushed (or by hand for an existing tag). The tag must match the `version:` in `pubspec.yaml` without the build number (`v1.1.6` for `1.1.6+8`). It writes `android/key.properties` from the secrets, builds the split APKs, checks with `apksigner` that they carry the project's signing certificate (`EXPECTED_CERT_SHA256`, also printed in the README), writes release notes from the commit subjects since the previous tag, publishes the GitHub Release with both APKs and deletes the signing material.

**Releasing.** Bump `version:` in `pubspec.yaml` (both the name and the build number; Android refuses an update with a lower build number), merge to `main`, then push the tag: `git tag v1.1.6 && git push origin v1.1.6`.

**Secrets** (repository secrets): `KEYSTORE_BASE64` (the PKCS12 release keystore, base64-encoded), `KEYSTORE_PASSWORD`, `KEY_ALIAS` and `KEY_PASSWORD`. Every release must be signed with this same key, or installed copies cannot update.

**Gradle cache in CI.** `~/.gradle/caches` and the wrapper are cached under a key built from the Flutter version, the Gradle files and `pubspec.lock`. `ci.yml` saves it on `main`; `release.yml` only restores it. Actions are pinned to commit SHAs with the version in a comment; update both together.

## Architecture

Riverpod (state and dependency injection) and go_router (routing) over Clean Architecture. Providers are the dependency graph: there is no `get_it` and no `injectable`.

```text
lib/
  main.dart                    only calls bootstrap()
  app/                         wiring: knows every layer, no module imports it (except the allowed folders below)
    bootstrap/                 bootstrap.dart, app_initializer.dart, provider_error_observer.dart
    di/                        core_providers.dart (one provider per core object)
    routes/                    app_routes.dart (AppRoutes), app_router.dart (routerProvider, AppRouter, go_router; unknown paths open NotFoundView)
    shell/                     app_shell.dart: persistent_bottom_nav_bar_v2's Style 8 bar around the four tabs, a NavigationRail from 600 dp; app_branch_switcher.dart (the tabs' fade-through), tab_scroll.dart (a tap on the open tab goes to the top)
    launch/                    launch_intro.dart, the splash hand-off into the Home header
    theme/                     themeModeProvider, accentProvider (Notifiers) and system_bars.dart
    shared/                    session-wide state every module reads: shared/domain/entities/quality.dart, download_prefs_provider.dart, platform_traits_provider.dart
  core/                        cross-cutting, state-management-neutral, imports no app/ or modules/
    config/                    environment.dart
    crash/ errors/ logging/ networking/ usecase/ utils/ widgets/
    platform/                  fetchr_api.g.dart, the generated pigeon client (see Native layer); platform_traits.dart
    gen/                       flutter_gen output (assets.gen.dart), committed
    services/                  storage/
    theme/                     app_colors.dart (the seed), app_tokens.dart, app_theme.dart, ...
  modules/<module>/            one folder per feature
    data/{datasources,models,repositories}
    domain/{entities,extensions,repositories,usecases}
    di/                        the module's providers: datasource, repository, use cases
    presentation/{formatters,providers,views/widgets}
```

No file sits at the root of a module's `domain/` or `presentation/`. A rule about the data that is not an entity is a getter on the entity (`DownloadTask.cardState`) or an extension in `domain/extensions/<type>_extensions.dart` (`List<DownloadTask>.groupedAt`, `String?.firstUrl`). UI copy built from a type is an extension in `presentation/formatters/<type>_formatter.dart` (`DownloadTaskFormat`, `QualityFormat`, `LibraryItemFormat`); it is presentation, not domain, because localising it will need `AppLocalizations` from Flutter, which G2 keeps out of domain. Copy shared by several modules (sizes, durations, dates, `plural`) is in `core/utils/formatters.dart`.

A module with no data or domain layer stays flat (`providers/`, `views/`). Code only one module uses lives in that module; it goes to `core/` only when it is shared and imports nothing from `app/` or `modules/`. Never create `lib/features/` or `lib/app/modules/`.

### Layer rules

| Layer | May import | Must not import |
| --- | --- | --- |
| `core` | itself, Flutter, plain packages (dio, equatable, ...) | `app/`, `modules/`, `get`, `get_it`, `injectable`, `flutter_bloc`, `bloc`, `flutter_riverpod`, `riverpod` |
| `domain` | itself, `equatable`, `core` | `data/`, `di/`, `flutter`, `get`, `get_it`, `dio`, `flutter_bloc`, `riverpod` |
| `data` | `domain`, `core`, `dio` | presentation, `di/`; never calls `ref.read` or `ref.watch` |
| `presentation` | `domain`, `core`, `flutter_riverpod`, `go_router`, its own module's `di/`, Flutter | `data/` (talk to use cases only) |
| module (any layer) | from `app/` only `routes/`, `shared/`, `theme/`; a `providers/` folder and the module's `di/` folder may also import `app/di/` | the rest of `app/` |
| module `di/` | `data`, `domain`, `core`, `app/di/`, `flutter_riverpod` | nothing in `data` or `domain` imports it |

Conventions that go with them:

- **`Result<T>`** (`core/errors/result.dart`) is `Ok(value)` or `Err(failure)`. `result.fold(onErr, onOk)` takes the failure first. Repositories, datasources, use cases and `DioClient.makeRequest` all return `Future<Result<T>>`. `guard(() async => ...)` wraps a throwing body into a `Result`.
- **`Failure`** subclasses carry `message` and `code`, and both take part in equality. Notifiers and views branch on the type or the code, never on message text.
- **Vocabulary:** folders `datasources`, `repositories`, `usecases`, `entities`, `models`; files `*_usecase.dart`; classes `I*` for abstract repositories and datasources, `*Impl` for implementations, `*UseCase` for use cases. Entities are pure Equatable; JSON lives in models that extend them.
- **Constructor injection everywhere.** Classes take their dependencies as `final` fields. Only the providers (`lib/app/di/`, `modules/<m>/di/`), notifiers and widgets use `ref`; there is no `sl`.
- **Core is plain.** Core classes (`DioClient`, `TokenStore`, ...) know nothing about Riverpod. The app layer injects behaviour into them, for example `AppInterceptors.onUnauthorized` is set in `AppInitializer`, so a 401 never reaches into a notifier from core.
- **Endpoints belong to the datasource** that calls them, not to `ApiConstants`.
- **Repositories check connectivity first** with `INetworkInfo` and return `Err(NetworkFailure())` when offline, for calls that need the network. Fetchr has no backend of its own, so the probe hits `https://connectivitycheck.gstatic.com/generate_204` and any HTTP answer counts as online. Which calls check is listed under "Deviations from the module recipe".
- **Logging:** only `AppLogger` (`debug`, `info`, `warning`, `error`). It redacts tokens, bearer headers, JWTs and coordinates. Never log tokens or PII. Exception messages reach Sentry unredacted: never put a token or a response body in an exception message. `print`, `debugPrint` and `dart:developer` are banned outside `lib/core/logging`.
- **Imports:** relative inside `lib/` (`prefer_relative_imports`, `directives_ordering`); `package:grabby/...` from `test/` and `tool/`. A relative `../lib/` path from a test loads a second copy of the library.
- **Comments:** only a non-obvious why. No banners, no doc comments that restate the code.
- **Size:** no file over 800 lines (aim for under 250).

### Architecture gates

`tool/ci/arch_gates.py` enforces the table above. It reads the package name from `pubspec.yaml` and the state management from its dependencies (`get` is getx, `flutter_bloc` is bloc, `flutter_riverpod` is riverpod), and drops or adapts the gates that only make sense for one of them.

| Gate | Rule |
| --- | --- |
| G-core | `core` imports nothing from `app/` or `modules/` |
| G-core-neutral | `core` imports no get, get_it, injectable, flutter_bloc, bloc, flutter_riverpod, riverpod |
| G1 | `domain` imports nothing from `data/` or `di/` |
| G2 | `domain` imports no Flutter, GetX, GetIt, Dio, Bloc or Riverpod |
| G3 | module `presentation` imports nothing from `data/` |
| G4 | `data` imports nothing from `presentation/` or `di/` |
| G9 | *getx only.* `bindings/` do not register repositories or datasources |
| G10 | `data` and `domain` never resolve from a service locator: `sl`, `getIt`, `locator`, `GetIt.I`/`GetIt.instance`, `Get.find` (riverpod also `ref.read`, `ref.watch`, `ref.listen`) |
| G-app | modules import only `app/routes`, `app/shared`, `app/theme`; DI-entry folders also `app/di` |
| G-log | no `print`, `debugPrint`, `dart:developer` outside `lib/core/logging` |
| G-size | no lib file over 800 lines |

The DI-entry folders are `providers/` (under `presentation/`) and the module's `di/`. `di/` is the module's wiring layer: it may import `data/` (G3 does not apply to it), and `data/` and `domain/` may not import it (G1, G4).

Existing violations sit in `tool/ci/arch_baseline.json`, counted per gate and file; it starts as `{}`. A new or grown violation fails, and so does a fixed one until `--update-baseline` locks it in, so counts only go down. A gate whose scope matches no file reports `VACUOUS` and passes (for example a gate for a layer the app does not have yet); `--self-test` guards the scopes. Never hand-edit the baseline to let new code through; fix the code. `python tool/ci/arch_gates.py --self-test` checks the gates themselves, including the per-state-management switch.

## Dependency injection

Two different jobs get called "DI", and each state management solves them its own way:

1. **Building the object graph** (Dio, storage, datasources, repositories, use cases).
2. **Providing it to the UI** (controllers, cubits, notifiers) with a lifecycle tied to a screen.

| | getx | bloc | riverpod (this app) |
| --- | --- | --- | --- |
| Object graph | `get_it` (`sl`) + `injectable` | `get_it` + `injectable` | providers |
| UI objects | GetX `Bindings` (`Get.lazyPut`) | `BlocProvider(create: ...)` in `lib/app/routes/` | `Notifier` / `Provider` |
| Package needed | get, get_it, injectable | flutter_bloc, get_it, injectable | flutter_riverpod only |
| Test override | register a fake on `sl`, `Get.put` a fake controller | `sl.registerFactory` a fake | `ProviderScope(overrides: [...])` |

### Riverpod variant (this app): providers are the container, no `get_it`

Riverpod already is a dependency injection container. A provider declares how to build a value and which other providers it needs:

```dart
final fetchMediaInfoUseCaseProvider = Provider<FetchMediaInfoUseCase>(
  (ref) => FetchMediaInfoUseCase(ref.watch(downloaderRepositoryProvider)),
);
```

Providers are lazy, built on first read, cached, and referenced by variable name, so a missing provider is a compile error, not a runtime "not registered". Tests replace any node with `overrideWithValue`, on a `ProviderContainer(overrides: [...])` or on `ProviderScope(overrides: [...])`.

So **adding `get_it` and `injectable` to a Riverpod app is a mistake**: it creates a second container that can disagree with the first, `ref` is not available inside a `get_it` factory so the two graphs cannot depend on each other cleanly, and every test has to override both. This app has no `injection_service.dart`, no `@injectable` annotations, no generated DI file and no `_Probe` smoke test; `build_runner` only runs for `flutter_gen`.

How the layers map:

- **`core` stays plain.** `DioClient`, `TokenStore` and the other core classes take their dependencies in constructors, so the same classes work with any container. `lib/app/di/core_providers.dart` holds one provider per core object (`secureStorageProvider`, `sharedPreferencesProvider`, `internetConnectionProvider`, `appStorageProvider`, `tokenStoreProvider`, `networkInfoProvider`, `dioProvider`, `dioClientProvider`, `fetchrHostApiProvider`, `platformTraitsProvider`).
- **A module's graph lives in the module.** `modules/<m>/di/<m>_providers.dart` declares the repository and use-case providers (plus a datasource provider in a module that has one), for example `Provider<IDownloaderRepository>((ref) => DownloaderRepositoryImpl(ref.watch(fetchrHostApiProvider), ref.watch(networkInfoProvider), api.downloads))`. It imports the core providers from `lib/app/di/core_providers.dart`, which is why `di/` may import `app/di` (G-app) and `data/` (it is the wiring layer, so G3 does not apply). Nothing in `data/` or `domain/` imports it (G1, G4), and they never call `ref` (G10).
- **`presentation/providers/` holds the screen's notifier.** `LibraryNotifier extends AsyncNotifier<List<LibraryItem>>` is exposed as `libraryNotifierProvider = AsyncNotifierProvider.autoDispose<LibraryNotifier, List<LibraryItem>>(...)`. `build()` reads the use case through `ref.watch(getLibraryUseCaseProvider)` and returns the items, or throws the `Failure`. The view `ref.watch`es the `AsyncValue` and switches on it: `AsyncData` is the list (or `EmptyView`), `AsyncError` is `ErrorView` (a `Failure` shows its `message`, anything else `ErrorMessages.unexpected`), anything else is loading. Retry is `ref.invalidate(libraryNotifierProvider)`; pull-to-refresh calls `refresh()`, which keeps the previous list on screen while it reloads.
- **Failures are retried by hand.** Riverpod 3 retries a failed provider up to ten times with backoff, which would hold the screen on loading before the error shows. `libraryNotifierProvider` passes `retry: (_, _) => null`; do the same for a notifier whose error is a `Failure` the user can retry.
- **Code outside the widget tree** (an interceptor hook; never code running in another isolate, which has no container) uses the one `ProviderContainer` that `bootstrap()` creates before `runApp`. `AppInitializer.init(container)` takes it and the app gets it through `UncontrolledProviderScope`, which is the Riverpod counterpart of `sl`.
- **Unexpected errors are reported.** Riverpod catches what a provider throws, so the zone hooks never see it. A `Failure` thrown from `build()` is state the view shows; anything else is a bug, and `ProviderErrorObserver` (`lib/app/bootstrap/`, installed on the container in `bootstrap()`) forwards it to `CrashReporting.recordError`.
- **The router is a provider.** `routerProvider` (`lib/app/routes/app_router.dart`) builds the one `GoRouter`: a `StatefulShellRoute` with the Home, Downloads, Library and Settings tabs inside `AppShell` (`lib/app/shell/`), its `navigatorContainerBuilder` an `AppBranchSwitcher` and each tab's page wrapped in a `TabScroll`, plus the top-level `AppRoutes.player`. Every route outside the tabs, and the shell itself, is a `MaterialPage` built by `AppRouter._route` / `_page`: go_router 18 looks for `material_ui`'s `MaterialApp`, not Flutter's, so its own pages would be `NoTransitionPage`s that never animate. `App` watches it. A test builds its own with `AppRouter.create()`.
- **App-wide state** such as the theme mode and the download preferences is a `NotifierProvider` (`themeModeProvider`, `downloadPrefsProvider`); `AppInitializer` awaits their `load()` before `runApp`. They are not in the smoke test `_graph`, which lists only the `final xProvider =` declarations under `di/`.
- **The smoke test is a guard.** `test/app/di/providers_smoke_test.dart` builds a `ProviderContainer` with only the platform edges faked, reads every provider listed in its `_graph`, and fails when that list differs from the `final xProvider =` declarations in `lib/app/di/` and `lib/modules/*/di/`. Declare providers at top level in that shape so it can see them.

The Bloc variant keeps `get_it` + `injectable` for the graph because Bloc has no container of its own: `RepositoryProvider` / `BlocProvider` are widget-tree scoped and cannot reach non-widget code.

## Add a module

For a feature `orders`:

1. **Folders:** `lib/modules/orders/{data/{datasources,models,repositories},domain/{entities,repositories,usecases},di,presentation/{providers,views/widgets}}`.
2. **Domain:**
   - `entities/order.dart`: `class Order extends Equatable`, no JSON.
   - `repositories/i_orders_repository.dart`: `abstract interface class IOrdersRepository { Future<Result<List<Order>>> getOrders(); }`.
   - `usecases/get_orders_usecase.dart`: `class GetOrdersUseCase implements BaseUseCase<List<Order>, NoParams>`; constructor takes the repository.
3. **Data:**
   - `models/order_model.dart`: `OrderModel extends Order` with `fromJson` / `toJson`.
   - `datasources/orders_remote_datasource.dart`: `IOrdersRemoteDataSource` plus `class OrdersRemoteDataSourceImpl`, calling `DioClient.makeRequest(path: 'orders', converter: ...)`. The path lives here.
   - `repositories/orders_repository_impl.dart`: `OrdersRepositoryImpl` takes the datasource and `INetworkInfo`, returns `Err(NetworkFailure())` offline.
4. **Providers:** `di/orders_providers.dart` declares `ordersRemoteDataSourceProvider`, `ordersRepositoryProvider` and `getOrdersUseCaseProvider`, each a top-level `final xProvider = Provider<Interface>((ref) => Impl(ref.watch(...)))` that reads core objects from `lib/app/di/core_providers.dart`.
5. **Presentation:**
   - `providers/orders_notifier.dart`: `class OrdersNotifier extends AsyncNotifier<List<Order>>`; `build()` calls the use case through `ref.watch(getOrdersUseCaseProvider)` and returns the value or throws the `Failure`; `refresh()` does `ref.invalidateSelf()` then awaits `future`, catching so a failed reload stays in state. Expose it as `final ordersNotifierProvider = AsyncNotifierProvider.autoDispose<OrdersNotifier, List<Order>>(OrdersNotifier.new, retry: (_, _) => null)`. Check `ref.mounted` after an `await` before writing `state`. Never build widgets or dialogs in a notifier.
   - `views/orders_view.dart`: a `ConsumerWidget` that `ref.watch`es the provider and switches on the `AsyncValue` using `LoadingView`, `ErrorView(onRetry: () => ref.invalidate(ordersNotifierProvider))`, `EmptyView`. An `AsyncData` that is also loading is a refresh: keep the list. Leaves go in `views/widgets/`.
6. **Route:** add `static const orders = '/orders';` to `AppRoutes` and a `_route(AppRoutes.orders, (_, _) => const OrdersView())` to `AppRouter.create` (never a plain `GoRoute(builder:)` there, which would not animate); navigate with `context.go(AppRoutes.orders)` (replaces the stack) or `context.push(AppRoutes.orders)` (adds to it).
7. **Tests** at the mirrored path under `test/modules/orders/{data,domain,presentation}/`: model JSON round trip, repository (offline gives `NetworkFailure`, online delegates), use case, notifier (loading to loaded, loading to failed, refresh, on a `ProviderContainer` with the use-case provider overridden), view (each state renders, retry reloads), and one `_graph` entry per new provider in `providers_smoke_test.dart`. Use `mocktail` and `test/support/`: mocks go in `mocks.dart` (one per repository and use case) and entity builders in `fixtures.dart`; add to them instead of declaring a private copy in a test file.
8. **Verify:** `bash tool/check.sh full`.

A module backed by the native layer (downloader, library, settings) has no datasource or model files in step 3 and no datasource provider in step 4; see "Deviations from the module recipe" under Native layer.

## Native layer

Every download runs in Kotlin: `youtubedl-android` 0.18.1 bundles yt-dlp, ffmpeg and aria2c, and the app calls it from `android/app/src/main/kotlin/com/defo/fetchr/` (package `com.defo.fetchr`). Native owns the task list and persists it; Flutter is a view onto it and never merges state. Dart reaches native only through the generated pigeon client in `lib/core/platform/`.

### Pigeon contract

- **Schema:** `pigeons/fetchr_api.dart`. It writes three outputs: `lib/core/platform/fetchr_api.g.dart`, `android/app/src/main/kotlin/com/defo/fetchr/pigeon/FetchrApi.g.kt` (Kotlin package `com.defo.fetchr.pigeon`, error class `FetchrError`) and `ios/Runner/Pigeon/FetchrApi.g.swift`.
- **Generate:** `fvm dart run pigeon --input pigeons/fetchr_api.dart`, then `fvm dart format lib/core/platform/fetchr_api.g.dart`. All three generated files are committed and never hand-edited; rerun this command instead. `tool/check.sh full` does not regenerate pigeon output, so after any schema change rerun the command and commit all three files.
- **Channel names carry the Dart package name** (`dev.flutter.pigeon.grabby.*`, from `dartPackageName: 'grabby'`). Renaming the package means regenerating, and `DOWNLOADS_CHANNEL` in `MainActivity.kt` must match.
- **Host API `FetchrHostApi`:** `fetchInfo`, `enqueue`, `cancel`, `retry`, `reorder`, `remove`, `listLibrary`, `deleteFromLibrary`, `share`, `openFile`, `openFolder`, `pickVideo`, `convertToMp3`, `pause`, `resume`, `pauseAll`, `resumeAll`, `freeSpaceBytes`, `thumbnail`, `ytDlpStatus`, `updateYtDlp`, `setYtDlpAutoUpdate`, `setAccentColor`, `trackPlayer`, `untrackPlayer`, `androidSdkInt`, `awaitLaunchSplash`. `androidSdkInt` is `Build.VERSION.SDK_INT`, read once by `AppInitializer` for `AppHaptics`. `pickVideo` is `@async` and returns the picked video's uri, or null when the user backs out: the photo picker (`android.provider.action.PICK_IMAGES`, no permission) on API 33, and on API 30 to 32 with the system update that brings it, else `ACTION_OPEN_DOCUMENT`; it persists read access when it can, so a retry after a restart still reads the video. `convertToMp3(uri, folder)` is `@async` and queues an MP3 task whose `url` is that `content:` or `file:` uri (see `LocalVideo.kt`). `remove` and `deleteFromLibrary(uri)` are `@async` and return a `bool`; `deleteFromLibrary` deletes one MediaStore item through `MediaLibrary.deleteFile` and returns false when the user declines the dialog; once the file is gone it also drops the completed task that saved it (`DownloadRepository.forgetSaved`), so Downloads and Home's Recent forget it too. For a completed task with a `savedUri`, `remove` deletes the MediaStore file first (without a consent dialog, a file already gone counts as deleted), then the task, and returns false with the task kept when the user declines the system delete dialog. `openFolder(uri)` is `@async` and returns nothing: it opens the folder holding that MediaStore item (`Movies/<folder>`, `Music/<folder>` or `Pictures/<folder>`) in the Files app, and throws `no_folder_app` when the item has no row or no app can open it; Android cannot highlight the file itself. `trackPlayer(handle)` and `untrackPlayer(handle)` take a media_kit player's libmpv handle; the player factory calls them, and `untrackPlayer` also clears that player's mpv wakeup callback. Before the engine is destroyed, `MainActivity.cleanUpFlutterEngine` detaches every tracked player (`MpvGuard.kt` with the JNI shim in `android/app/src/main/cpp/`: wakeup callback cleared, `quit`) and then releases media_kit_video's surfaces (`VideoSurfaces.kt`); otherwise a player left open when Android destroys the Activity, while `DownloadService` keeps the process alive, aborts the process from mpv's thread or Flutter's renderer. `awaitLaunchSplash()` is `@async` and completes once the Android 12+ launch splash has played its icon animation and gone (at once below Android 12, and when the activity is destroyed); `LaunchIntro` bounds the wait at 1.2 s, because no exit listener fires when the system shows no splash. `@async` methods are generated as Kotlin `suspend fun`s that `setUp` launches on `Dispatchers.Main`, so blocking work goes in `withContext(Dispatchers.IO)`.
- **Event channel `FetchrEvents.downloads()`** is the top-level Dart function `downloads()`. It emits the full `DownloadsSnapshot` on listen and on every change, at most one per 250 ms. The generated factory opens a new `EventChannel` on each call, so the repository calls it once.
- **Types:** a Dart `int` arrives in Kotlin as `Long` and a `double` as `Double`. `progress` is 0..1, with -1 meaning unknown (starting, merging, and an MP3 conversion until ffmpeg's first report); `etaSeconds` is -1 when unknown. The pigeon classes share names with the domain entities (`DownloadRequest`, `DownloadTask`, `LibraryItem`, `PlaylistEntry`, `Quality`, `TaskStatus`), so data files import the generated file with a prefix: `import '../../../../core/platform/fetchr_api.g.dart' as api;`.

Native throws `FetchrError(code, message, null)`, which Dart receives as `PlatformException(code: ...)`. `failureFrom` in `core/errors/failure_mapper.dart` has a `PlatformException` arm that calls `failureFromCode`, so `guard()` maps every pigeon call. A failed task carries the same string in `DownloadTask.errorCode`, a `String?` and not an enum, and the repository passes it straight to `failureFromCode`. The raw yt-dlp line in `errorMessage` reaches the domain task only for an `unknown` failure.

| Code | Failure | When |
| --- | --- | --- |
| `unsupported_site`, `invalid_url` | `UnsupportedSiteFailure` | yt-dlp has no extractor, or the URL is not `http(s)` |
| `private_video` | `PrivateVideoFailure` | private, age-gated, members-only, needs sign-in |
| `unavailable` | `MediaUnavailableFailure` | removed, geo-blocked, 404 |
| `network` | `NetworkFailure` | DNS, timeout, connection reset |
| `no_storage` | `StorageFailure` | disk full or write denied |
| `busy` | `YtDlpBusyFailure` | `updateYtDlp` while a download or info fetch runs |
| `no_folder_app` | `UnexpectedFailure(ErrorMessages.noFolderApp)` | `openFolder` when the item has no row or no app can open the folder |
| `permission_denied` | `StoragePermissionFailure` | a write the OS or the user's permission refused (EACCES), on Android and iOS |
| `unknown`, anything else | `UnexpectedFailure(ErrorMessages.downloadUnknown)` | the native `message` is the last yt-dlp `ERROR:` line |

- **URLs are checked natively.** `RequestBuilder.requireHttpUrl` is the trust boundary: a URL starting with `-` would be read by yt-dlp as an option. The Dart `extractUrl` only helps the paste box.
- **Request shape.** Every download passes `--no-playlist --no-mtime --cache-dir`, `-N 4` and an output template under the task's temp dir. `-N 4` (`--concurrent-fragments`) only parallelises HLS and DASH fragments, because aria2c takes only http(s) and ftp(s) files since yt-dlp 2026.06.09; it does nothing for single files and covers and applies with or without aria2c. 4 keeps two tasks to at most 8 requests at a server (a benchmark showed no gain past about 10). Video uses `-f bv*+ba/b` with `-S res:<cap>,vcodec:h264,acodec:aac` (`-S res,...` for best) and `--merge-output-format mp4`; the cap comes from `Quality.shortSideCap` (1080, 720, 480) and yt-dlp's `res` is the smaller of width and height, so a portrait 1080x1920 clip counts as 1080p. MP3 uses `-x --audio-format mp3 --audio-quality 0` and `--postprocessor-args "ExtractAudio+ffmpeg:-progress <task dir>/ffmpeg.progress"`: yt-dlp keeps ffmpeg's output to itself, so ffmpeg's report file is the only progress while it converts (out_time over the request's duration; unknown without one); a local video (`LocalVideo`) runs the same MP3 options through `RequestBuilder.convert`, which adds `--enable-file-urls` for that request only; cover uses `--skip-download --write-thumbnail --convert-thumbnails jpg`, which leaves one `.jpg` in the task dir for the largest-file pick in `DownloadRepository`; aria2c adds `--downloader libaria2c.so` and one `--downloader-args "aria2c:--summary-interval=1 --ca-certificate=<cert>"` (the library sends those two separately and yt-dlp keeps only the last, which would drop the interval and the progress lines). aria2c is skipped for YouTube hosts (youtube.com and subdomains, youtu.be, youtube-nocookie.com, matched on the parsed host), even with "Faster downloads" on: yt-dlp's maintainers strongly discourage it there, and YouTube throttles requests over 10 MB, which the native downloader avoids with 10 MiB chunks.
- **Options and sizes.** `fetchInfo` returns `VideoInfo.options`, the one list the quality picker shows. For a single video `InfoParser` picks the stream yt-dlp would pick for best, 1080p, 720p and 480p: video formats with a width and a height, the largest short side within the cap (or the smallest one above it when none fits), then yt-dlp's own order for `-S vcodec:h264,acodec:aac`: the video codec closest to h264 (h264, then the older codecs, then h265, vp9, av1), the audio codec closest to aac (so a progressive stream beats a video-only one of the same codec), then higher frame rate, larger size and higher bitrate. A tier whose pick has the short side of an earlier option is dropped. A video-only pick adds the best audio stream (`mp4a` first, then bitrate), and the size is the sum of the parts: `filesize`, else `filesize_approx`, else `tbr` times the duration, with `sizeIsEstimate` set when any part was not exact and the size left null when any part has none. MP3 is offered when an audio or progressive stream exists (its size is the best audio stream's, always an estimate), and cover when the info has a thumbnail (its size comes from the matching `thumbnails` entry, if any). A playlist, or a video with no `formats`, gets best, 1080p, 720p, 480p and MP3 without metadata (and no cover for a playlist); video formats without dimensions give best and MP3.
- **Android's `org.json` returns `"null"` for JSON null** from `optString`; read optional strings through the `str` extension in `Json.kt`, which checks `isNull` first, as `InfoParser.kt` and `TaskCodec.kt` do.
- **Kotlin changes need a rebuild and reinstall.** Hot reload and hot restart do not reach them.
- **Packaging.** `useLegacyPackaging = true` in `android/app/build.gradle.kts` extracts libpython, ffmpeg and aria2c so they can run from `nativeLibraryDir`. `android/app/proguard-rules.pro` keeps `com.yausername.**` and `org.apache.commons.compress.archivers.zip.**` under R8; Flutter's Gradle plugin picks the file up.

### Foreground service and notifications

- **`DownloadService`** is a started service, not a bound one. `DownloadRepository.enqueue` starts it. It calls `startForeground` with `FOREGROUND_SERVICE_TYPE_SPECIAL_USE` on API 34+ (the manifest declares `foregroundServiceType="specialUse"` plus the subtype property, and `specialUse` has no Android 15 timeout), holds a partial WakeLock while it runs, and stops itself when no download is active.
- **Progress notification:** channel `downloads` (`IMPORTANCE_LOW`), ongoing, `setOnlyAlertOnce`, indeterminate while progress is below 0, one "Cancel all" action through `PendingIntent.getService`. `onTimeout` cancels everything. The service is `START_NOT_STICKY`: a killed process does not resume downloads, and the interrupted tasks load as failed with the message "Interrupted", so the user retries them.
- **Result notifications:** `DownloadNotifications.finished` runs on every transition to completed or failed, on channel `download_results` (`IMPORTANCE_DEFAULT`, auto-cancel). A completed tap opens the saved file with `ACTION_VIEW`; a failed tap opens the app; a cancelled task posts nothing. It skips silently when `POST_NOTIFICATIONS` is not granted. All of this is native and works with the app closed; there is no Flutter notification plugin.
- **Permissions** are declared in `AndroidManifest.xml` and requested from Dart by `AppInitializer` after the first frame (notification, storage, videos, audio). Denial is fine: downloads still run and Android 10+ saves without storage access.

### MediaStore locations

- **Android 10+ (API 29+):** `MediaLibrary.save` inserts, by `MediaKind`, into `MediaStore.Video.Media` (`Movies/<folder>`), `MediaStore.Audio.Media` (`Music/<folder>`) or `MediaStore.Images.Media` (`Pictures/<folder>`, for a cover), on `VOLUME_EXTERNAL_PRIMARY`, with `IS_PENDING=1` while it copies and `0` after; a failed copy deletes the row. No storage permission is needed.
- **Android 8 to 9 (API 26 to 28):** copies into the public `Movies`, `Music` or `Pictures` directory (a " (n)" suffix on a name clash) and runs `MediaScannerConnection`. This needs `WRITE_EXTERNAL_STORAGE`, declared with `maxSdkVersion` 28.
- **Listing** reads the same relative paths for videos and audio; covers are saved but never listed. Files from an earlier install need `READ_EXTERNAL_STORAGE` (max 32) or `READ_MEDIA_VIDEO` and `READ_MEDIA_AUDIO`.
- **Delete** tries `ContentResolver.delete`. For files the app does not own it asks for consent: `MediaStore.createDeleteRequest` on API 30+, or the `RecoverableSecurityException` intent sender on API 29, both through `MainActivity.launchIntentSender`. `HostApi.remove` and `HostApi.deleteFromLibrary` both go through `MediaLibrary.deleteFile`. Removing a completed download deletes its file first, and the task stays when the user declines the dialog (the dialog's answer is final: an unowned row is invisible to the app's own query, so `deleteFile` never re-checks existence after a consent request). Without a dialog a file that is already gone, or a uri that is neither MediaStore nor `file:`, counts as deleted. A `file:` uri (API 26 to 28, when the media scan fails) is deleted with `File.delete()`, and the task stays when that fails.
- **Open folder** reads the item's `RELATIVE_PATH` (API 29+) or the parent of `DATA` (API 26 to 28; a `file:` uri uses its own path) and starts `ACTION_VIEW` on `DocumentsContract.buildDocumentUri("com.android.externalstorage.documents", "primary:<folder>")` with the directory mime type, which the Files app resolves. Primary volume only. A missing row or `ActivityNotFoundException` throws `FetchrError("no_folder_app", ...)`.
- **The default folder is `Fetchr`.** `RequestBuilder.safeFolder` strips `\ / : * ? " < > |` and leading dots and falls back to `Fetchr`; the Settings dialog rejects the same characters.

### yt-dlp updates

- **Init:** `FetchrApp.onCreate` calls `YtDlp.start`, which initialises YoutubeDL, FFmpeg and Aria2c on an IO scope. Every run awaits `YtDlp.ready`, so an init failure shows up as an `unknown` error on the first call.
- **Daily update:** after init, `YtDlp` updates yt-dlp from the stable channel when 24 hours have passed. The timestamp lives in the `fetchr_native` SharedPreferences and is written only after a successful update; a failure is logged, never fatal, and retried at the next start.
- **Manual update:** Settings calls `updateYtDlp` (Dart checks connectivity first). The update swaps the zipapp in place, so it throws `busy` while any run is active and new runs wait until it finishes. When downloads start failing as `unknown`, update yt-dlp first.

### Deviations from the module recipe

The downloader, library and settings modules differ from "Add a module" because their data source is the native layer, not an HTTP API.

- **Repositories take the generated `FetchrHostApi`** (`api.FetchrHostApi`, from `fetchrHostApiProvider`) as a constructor argument. There is no `datasources/` folder and no `models/` folder: the pigeon classes are the DTOs, and each repository holds private mapper functions from them to the domain entities. Entities stay pure Equatable. Use cases stay one per operation.
- **The generated client sits in `core/platform/`.** It is plain Dart with no Riverpod, so core stays neutral; the app layer provides it in `lib/app/di/core_providers.dart`.
- **`app/shared/` holds what several modules read:** the `Quality` entity and `downloadPrefsProvider` (`DownloadPrefs`: quality, folder, aria2c). Downloader reads them for new downloads, library for the folder and settings edits them. They are persisted through `appStorageProvider` under `StorageKeys.defaultQuality`, `saveFolder` and `useAria2c`, and loaded in `AppInitializer`. The provider is not in the smoke test `_graph`, like `themeModeProvider`.
- **Connectivity is checked only for network-bound calls:** `fetchInfo` and `updateYtDlp`. Enqueue, cancel, retry, remove, `openFolder`, `pickVideo`, `convertToMp3`, library calls and `ytDlpStatus` are local and never return `NetworkFailure` from the probe. The probe is `https://connectivitycheck.gstatic.com/generate_204`, and any HTTP answer counts as online.
- **Native error codes live in `core/errors`:** the five failures, `failureFromCode` and the `PlatformException` arm of `failureFrom`. A repository only wraps its call in `guard()`.
- **The task list is a stream, not a request.** `DownloadsNotifier` is a `StreamNotifier` over `watchTasks()`, with `retry: (_, _) => null`. The notifier does no merging.
- **Repository tests fake the host API:** `class _MockApi extends Mock implements api.FetchrHostApi`, with `INetworkInfo` mocked next to it. View tests pump the real router through `test/support/fake_app.dart`, which overrides the three repository providers.
- **The demo `home` module is gone.** `AppRoutes` has `home`, `downloads`, `library`, `settings` and `player`.

## iOS native layer (in progress)

Phase 1 (skeleton plus the embedded Python runtime), phase 2 (YouTube through JavaScriptCore, in-process ffmpeg, first downloads) and phase 3 (the full download repository: cancel, pause, resume, retry, remove, reorder, persistence) are done: `fetchInfo`, `ytDlpStatus`, `enqueue`, the downloads stream, `cancel`, `retry`, `reorder`, `pause`, `resume`, `pauseAll`, `resumeAll` and `remove` work on the iPhone (`setAccentColor` and `setYtDlpAutoUpdate` only store the value, `awaitLaunchSplash` returns at once), and so does the library (the first part of M7): `listLibrary`, `deleteFromLibrary`, `thumbnail`, `freeSpaceBytes`, `share`, `openFile` and `openFolder`. M7 part 2 is built, and its on-device check (the owner's manual check list) is still to run: `pickVideo` and `convertToMp3` turn a video picked from Photos into an MP3 in `Music/<folder>`; `updateYtDlp` installs the latest release after checking its SHA-256, and the next launch runs the newest good copy after a selftest, rolling back to the previous one or the bundled copy when it fails (see the yt-dlp bullets below); and the Dart UI speaks iOS through `PlatformTraits` (see Dart on iOS). M7 part 3 is built too, also awaiting its manual check: the share extension (see Share extension), the app icon and launch screen (`tool/ios/render_icons.swift`, see Glyph copies) and the bundled components' licences (`tool/ios/collect_licenses.py`), reachable on both platforms from Settings › About › Open-source licences. Downloads stop in the background and post no notifications: that is M6, on a device. The design is in `docs/plans/2026-11-14-ios-native-design.md` (local, not tracked).

- **Contract:** the same `pigeons/fetchr_api.dart`; its `swiftOut` writes `ios/Runner/Pigeon/FetchrApi.g.swift`. Regenerate with the same pigeon command and commit all outputs. Swift language mode stays 5.0 because pigeon's Swift output does not compile in 6. Deployment target is iOS 26.0.
- **Split:** C (`ios/Runner/Fetchr/Python/FetchrPython.c`) owns the interpreter and the GIL, Swift (`PythonRuntime.swift`, `HostApi.swift`, `RequestBuilder`, `InfoParser`, `ErrorClassifier`) is the host and the pure ports of the Kotlin classes, Python (`ios/app/fetchr_bridge`) wraps yt-dlp and replies with a JSON envelope (`{"ok":true,"value":...}` or `{"ok":false,"hint":...,"message":...}`). `fetchr_py_call(name, payload_json, &error)` returns that envelope, or NULL with a plain error text when Python could not reply; neither C nor Swift builds an envelope. Python tests are in `ios/python_tests`, Swift tests in `ios/RunnerTests/Fetchr`.
- **Never take the GIL on the main thread.** Pigeon calls arrive on main; `PythonRuntime.call` awaits boot and runs each call on its own `Thread` with an 8 MB stack, so a long download never starves an info call. Python boots on its own 8 MB thread at launch, which then stays parked so `threading.main_thread()` stays alive (about 0.4 s on the simulator right after an install; read it in Console as `Python ready in N ms`, subsystem `com.defo.fetchr`, category `python`).
- **Bytecode ships, it is never written.** The bundle is read-only, so `write_bytecode` is off and there is no pycache in Caches. The stdlib's `__pycache__` comes with the XCframework, `vendor_python.sh` compiles `app_packages` (unchecked-hash pycs), and the `fetchr_bridge` files compile at import. An installed yt-dlp update is the one exception: the bridge's `compile` call writes its timestamp pycs once, at install, before `.complete` (1 s on the simulator; it saves about 175 ms of every boot, 475 to 300 ms), and a failed compile still installs, since the sources import.
- **Scripts in `tool/ios/`, in order:** `fetch_python.sh` (pinned CPython iOS XCframework into `ios/Python.xcframework`, minus the stdlib test, IDLE, Tk, ensurepip and test-extension modules), `vendor_python.sh` (pinned pure-Python packages from `requirements.txt` into `ios/app_packages`, bytecode compiled), `build_ffmpeg.sh` (FFmpegKitNext at a pinned tag and sha, FFmpeg plus libmp3lame, LGPL, arm64 device and simulator slices, into `ios/Frameworks/ffmpegkit`; a stamp makes reruns a no-op; a fresh build takes a few minutes and needs `brew install autoconf automake libtool pkgconf gnu-sed gettext`), `configure_xcode.sh` (syncs `Runner.xcodeproj` with the Swift/C files and embeds Python and the fixed list of FFmpegKit xcframeworks; rerun after adding or removing a Swift or C file), `collect_licenses.py` (copies the licences of CPython, FFmpeg/FFmpegKit/LAME (LGPL-3.0 plus the GPL-3.0 text from `tool/ios/licenses/`) and every vendored Python package, with the yt-dlp-ejs solver's bundled-dependency notices, into the committed `assets/licenses/ios/` and its `manifest.json`; rerun it after a pin changes; `bootstrap` adds them to the licence page through `PlatformTraits.nativeLicenseManifest`, iOS only), `install_python.sh` (the Xcode build phase body; Xcode runs it, never run it by hand), `test.sh [--swift|--python]` (XCTest on iPhone 17 plus pytest). The Python version is `tool/ios/python-version` alone (bump it with the sha256 in `fetch_python.sh`); every script and `PythonRuntime` derive the version from it or from the bundle. `ios/Python.xcframework/`, `ios/app_packages/`, `ios/Frameworks/ffmpegkit/` and `ios/Flutter/Signing.xcconfig` are gitignored; the xcconfig holds the developer team for device builds and `Debug.xcconfig`/`Release.xcconfig` include it optionally.
- **Clean clone:** `uv` and Homebrew CocoaPods are required. Run `fvm flutter pub get`, `bash tool/ios/fetch_python.sh`, `bash tool/ios/vendor_python.sh`, `bash tool/ios/build_ffmpeg.sh`, then `fvm flutter build ios --simulator --debug`; run `bash tool/ios/configure_xcode.sh` after adding a Swift or C file.
- **No sound from the in-app player on the simulator, by design:** media_kit's prebuilt `Mpv.xcframework` simulator slice is built with `-Daudiounit=disabled`, so libmpv has only the `null` audio output there; the device slice has AudioUnit and plays sound. Test audio on an iPhone (the Files app plays the same files with sound on the simulator).
- **Two FFmpeg builds share the app.** media_kit embeds its own FFmpeg as `Avcodec.framework`, `Avformat.framework`, ... (capitalised); FFmpegKit's are `libavcodec.framework` and so on, next to `ffmpegkit.framework`. Their install names differ, so both sets load in one process.
- **Network tests are opt-in:** `FetchInfoIntegrationTests`, `YouTubeIntegrationTests` and `DownloadIntegrationTests` (the M4 gate: a direct mp4, YouTube 720p merged to h264 + aac mp4, YouTube MP3, and `fetchInfo` answering while two downloads run; the M5 gate: pause a YouTube 720p download past 5 MB, rebuild the repository on the same store and dirs, resume and check the first progress continues from the `.part`; cancel then retry from zero; ten queued downloads that start in a reordered order and save as `name.mp4` to `name (9).mp4`; each test on its own temp Documents, Caches and store, never `Paths.*`) skip unless `FETCHR_NETWORK_TESTS=1`; pass it to xcodebuild as an environment prefix, `TEST_RUNNER_FETCHR_NETWORK_TESTS=1 xcodebuild test ...` (a trailing argument becomes a build setting and the tests skip). `TEST_RUNNER_FETCHR_KEEP_DOWNLOADS=1` moves each test's Documents to `Documents/Tests/<test name>` for a look in the Files app. Add `-parallel-testing-enabled NO` to see the tests' `print` lines (timings) in xcodebuild's output; parallel clones swallow them. A multi-homed IPv6 Mac can get YouTube 403s (the media URL is signed for one source address and fetched from another) and resets from MDN's IPv6 front on a process's first connection; the gate retries a download that failed on the network or with a 403 once, as a user would, and prints the first failure; any other failure fails the test.
- **YouTube's JS challenges run in JavaScriptCore:** `_fetchr.js_eval(src)` (`JavaScriptEval.c`, a fresh `JSContextGroup` per call, GIL released) evaluates a script and returns its last value as a string. `fetchr_bridge/jsc.py`, imported by `api.boot` before any `YoutubeDL`, registers a `javascriptcore` JS runtime and a challenge provider with preference 1000: plan A subclasses yt-dlp's internal `EJSBaseJCP` with `run_js` as its runtime; plan B, used when that import or contract breaks, solves through the public `JsChallengeProvider` API with the vendored `yt_dlp_ejs` scripts. `run._options` sets `js_runtimes={"javascriptcore": {}}` and `remote_components=["ejs:github"]`. A solve takes about 0.3 s on the simulator; os_log shows `JS challenge provider plan A` and `JS solve N ms` (category `python`).
- **YouTube's bot check falls back to IPv4:** YouTube can flag a network's IPv6 address ("Sign in to confirm you're not a bot") while IPv4 still passes. `run.info` and `run.download` then rerun the whole call once with `source_address=0.0.0.0` (the media URLs are signed for the address that asked, so the download goes over IPv4 too); any other error, or a second bot check, is not retried and the first error is reported.
- **yt-dlp is run through the API, not the CLI:** `run.info` sets `ignoreerrors=False`, because the CLI default makes `extract_info` return `None` on a failed extraction. The failure is then a `DownloadError` whose text is yt-dlp's `ERROR:` line, which the envelope passes on as `message`; the logger stays silent. `run.info` returns the sanitized info dict and the envelope encodes it once.
- **ffmpeg runs in-process:** `FFmpegBridge.m` is the only file that imports FFmpegKit; Python reaches it through `_fetchr.ffmpeg(argv, task)` and `_fetchr.ffprobe(argv, task)` (both return `(rc, out)`, 255 when cancelled, GIL released for the session) and `_fetchr.cancel_session(task)`, which also refuses (255) every later session of that task until `_fetchr.forget_session(task)`; the mark is checked where a run registers, so a cancel cannot slip between two sessions. `fetchr_ff_serialize` (on) lets one session run at a time. `fetchr_ff_run` messages `FFmpegKitConfig` before it creates a session: a session registers itself through a C function that does not run the class's `+initialize`, so the process's first session would lose its log and yt-dlp would cache its `-bsfs` probe as "no ffmpeg" until the app restarts (`FFmpegBridgeTests.testEverySessionKeepsItsLog` catches it when run alone). ffprobe's stdout is the text of a `-o` temp file the bridge adds itself, or the session log when that file is empty (`-bsfs`, `-version`, which is how yt-dlp detects it); a caller's own `-o` turns that off. `fetchr_bridge/__init__.py` installs `inproc_popen.InProcPopen` as `subprocess.Popen` at package import, before anything imports yt_dlp (`yt_dlp.utils.Popen` subclasses it at import time): `ffmpeg` and `ffprobe` become those calls, tagged with `inproc_popen.current_task`, and any other program raises `ENOENT`. Stop a task with `inproc_popen.cancel_task(id)` and call `forget_task(id)` when it ends or before a retry reuses the id; `kill`, `terminate` and `communicate("q")` do nothing, because the session has already ended. `api.boot` turns `FFmpegFD` off and `run` sets `hls_prefer_native`, so ffmpeg normally only post-processes files; yt-dlp still picks `FFmpegFD` for live HLS/DASH and for `rtmp`, `rtsp` and `mms`, which `run.download` refuses.
- **Download run:** Swift `RequestBuilder.downloadArgv` builds Android's download argv minus aria2c and without the URL, which goes next to it. The bridge's `download` handler (`{argv, url, task, outDir}`, returns `{"files": [...]}`, the names left in `outDir`) runs `run.download` with `inproc_popen.current_task` set: it extracts with `download=False`, refuses a live stream (`unsupported_site` "Live streams can't be downloaded on iPhone yet.") and any chosen format whose protocol starts with `rtmp`, `rtsp` or `mms` (`unsupported_site` "This stream can't be downloaded on iPhone yet."), then `process_ie_result(info, download=True)`. A `FetchrBridgeError`'s `hint` goes into the envelope as it is. Hooks emit `{"type":"progress","stage":"downloading","downloaded","total","speed","eta"}` at most every 250 ms (the first, a stage change and yt-dlp's `finished` always) and `{"type":"stage","stage":"postProcessing","pp":<name>}` when a postprocessor other than `MoveFiles` starts. `cancel` (`{task}`) marks the task, so its next hook raises `DownloadCancelled`, and calls `inproc_popen.cancel_task`; the run clears both and calls `forget_task` when it ends, whatever the outcome. A cancel that lands after its run ended leaves a mark that never clears; that is harmless because run keys (`<id>#<n>`) are never reused within a process, so never reuse one.
- **Downloads (`ios/Runner/Fetchr/Downloads/`):** `AppDelegate` owns one `DownloadRepository` (an actor), shared by `HostApi` and `DownloadsStream`, and sets `PythonRuntime.setEmitHandler` to its `receive(taskId:json:)`. `HostApi.enqueue` is the trust boundary: it runs `RequestBuilder.requireHttpUrl` on every URL first, so one bad link fails the whole batch with `invalid_url` and adds no task (as on Android), then hands the trimmed requests to the actor through `submit`. `submit` and `receive` only yield into one ordered `AsyncStream` the actor drains, so an emit callback never blocks a Python thread and events keep their order. New tasks go to the head of the list (`queued`, stage `preparing`, progress and ETA -1, one `createdAtMs` per batch); at most two run at once (see the next bullet for the queue). A run gets `Library/Caches/tasks/<id>` as `outDir`, calls the bridge's `download`, picks the largest regular file that is not `*.part`, `*.ytdl` or `ffmpeg.progress` (an MP3 task takes only `*.mp3`; none is `unknown` "No file was saved."), and `SaveLocation.save` moves it into `Documents/<Movies|Music|Pictures>/<folder>[/<playlist>]`, a taken name becoming `name (1).ext`, `name (2).ext`, ... as on Android. The task keeps `savedPath` (that relative folder); `savedUri` is the absolute `file://` URL, built per snapshot from the stored relative file, because the app container's path changes between installs. A failure is `failed` with `ErrorClassifier.classify`'s code and message (a Cocoa or POSIX file error maps to `no_storage`, `permission_denied` or `unknown` with friendly copy, never its path; a Python hint of `invalid_url`, `busy` or `no_folder_app` passes through). A playlist or multi-video result (a post with several videos) downloads its entries, each checked for live and streaming protocols, and the largest file is kept, as on Android; a cover skips those checks. Progress events set `progress` (`downloaded/total`, -1 without a total), bytes, speed, ETA and stage `downloading`; the `postProcessing` stage resets progress and ETA to -1; events for a task that is no longer running are dropped (they can arrive after the run's reply). `DownloadsStream` sends the list on listen and then at most one snapshot per 250 ms, always ending on the newest (the repository's subscriber streams keep only the newest list, and the forwarder sleeps 250 ms after each send). `Info.plist` sets `UIFileSharingEnabled` and `LSSupportsOpeningDocumentsInPlace`, so the Files app shows On My iPhone › Fetchr.
- **Repository semantics (`DownloadRepository.swift`, `+Run.swift`; the rules are pure ports: `TaskTransitions`, `TaskProgress`, `StartQueue`, `TempDirs`, `TaskCodec`):** every attempt (a start, a resume, a retry) runs under its own run key `"<taskId>#<n>"`, `n` counted per task from 1 in each process; it is the Python `task` id, the emit id and the owner token, so a late event, reply or cancel only ever touches its own attempt. `StartQueue` starts at most two runs in an order `reorder` can change (it also swaps the queued tasks' places in the list; not persisted, as on Android). Pause and cancel settle the task at once through Android's transitions, remove drops it, and all three free the slot; the abandoned Python call gets the bridge's `cancel` and unwinds in the background, and its reply changes nothing. The next attempt of the same task stays `queued`, without a slot, until the old one has ended (one chain per task), and goes on from the files in `Caches/tasks/<id>` (an MP3 attempt first deletes any finished `.mp3` and `ffmpeg.progress` there: ffmpeg writes the MP3 under its final name, and a conversion cut short would be taken as done), which is kept for a paused, failed or queued task and deleted otherwise. `remove` never shows a dialog and returns true: for a completed task it deletes the saved file (one already gone counts as deleted) and its playlist folder once empty, never `<Movies|Music|Pictures>/<folder>`; an I/O error throws and keeps the task.
- **Persistence:** `TaskStore` writes `Library/Application Support/downloads.json` (the folder is excluded from backup) atomically on its own serial queue, a newer list replacing a pending one. `TaskCodec` is Android's JSON plus `savedFile`, the saved file relative to Documents; `savedUri` and `stalled` are never stored. Every status change, enqueue and remove writes; queued to running and progress ticks do not. A corrupt file loads as an empty list and a malformed task is skipped. At launch a queued or running task loads as **paused** (not Android's failed "Interrupted"), at the progress of the last write (0 or more), with its partial files kept, and nothing starts by itself; dirs under `Caches/tasks` that no paused or failed task owns (`TempDirs.orphans`) are deleted off the actor, and every work on a task waits for that cleanup.
- **Stall and conversion:** every 5 s, a running attempt whose Python call has sent nothing for 30 s is flagged `stalled` (never while `postProcessing`, never while it waits for its turn); its next event clears it. An MP3 with a known duration reads ffmpeg's `ffmpeg.progress` every 500 ms while it post-processes, so the conversion shows a percent.
- **yt-dlp updates (`ios/Runner/Fetchr/YtDlp/`):** `YtDlpUpdater.update(running:)` reads GitHub's `releases/latest` (the tag is the version and must look like `2026.10.26` or `2026.10.26.1`), fetches the `SHA2-256SUMS` and `yt-dlp` assets (their links must be https on `github.com`, every answer after redirects must come from `api.github.com`, `github.com`, `objects.githubusercontent.com` or `release-assets.githubusercontent.com`, and both are saved under those fixed names, never the link's own), checks the zipapp's SHA-256 (CryptoKit) against its line, and `ZipExtractor` unpacks it into `Application Support/yt-dlp/<version>.partial`, renamed to `<version>` when every entry is written and CRC-checked; `yt_dlp/version.py` must declare the tag, then `.complete` is written last, and `installed()` lists only dirs that have it, newest first. The official zipapp is a zip after a `#!` line with offsets counted from after it, plain files only (deflate and stored), and carries `yt_dlp_ejs` (0.8.0 in 2026.10.26); the extractor refuses absolute paths, `\`, empty, `.` or `..` components, links and special files, encrypted, zip64 or multi-part archives and anything over 256 MB. A latest not newer than the running version, or already installed, downloads nothing. The newest two versions are kept, and the running one is never deleted; an update first clears what a kill left (`.download`, `*.partial`, a version dir without `.complete`) and never touches other files in the folder. `checkedAtMs` (`fetchr.ytDlpCheckedAt`) is written only after a success. `RunGate` is Android's: `beginSwap` throws `busy` while a run is active and the update holds it for its whole run, network included, under one 120 s deadline for the API, the sums and the zipapp together (then it fails as `network` with nothing installed and the gate released); hashing and unpacking run off the actor; every `info` and `download` Python call enters it first and leaves only when Python returns, so an abandoned attempt still unwinding counts, and an attempt paused while it waited never calls Python. `ytDlpStatus` reports the running version (`ping`), `updateYtDlp` the version it installed for the next launch (the running one when nothing newer came), both with `checkedAtMs` and `autoUpdate`. `YtDlpSchedule.isDue` is Android's 24 h rule.
- **Which yt-dlp a launch runs (`YtDlpLaunch.swift`, `YtDlpStartup.swift`, `fetchr_bridge/selftest.py`):** CPython cannot be re-initialised in-process, so `AppDelegate` decides before boot: `launchChoice(bundled:)` picks the newest installed version that is complete, carries its own `yt_dlp/__init__.py`, `version.py` and `yt_dlp_ejs/__init__.py` and no top-level name but `yt_dlp`, `yt_dlp_ejs`, `__main__.py`, `__pycache__` and `.complete` (`layoutProblem`, which also refuses such a zipapp at install; if a future yt-dlp zipapp ships another top-level entry, every update is refused as unverifiable until that list grows, so check it at each release), is not bad and is not older than the bundled copy (an equal one wins), else nil for the bundled copy, and writes it as `attempt` in `<root>/launch.json` (atomic). `PythonRuntime.start(ytDlpDir:)` puts that dir after `app` and ahead of `app_packages` (so its `yt_dlp` and `yt_dlp_ejs` win whole and can never shadow `fetchr_bridge`), and `fetchr_py_init` passes it as `-X fetchr_ytdlp_dir=<dir>` (`sys._xoptions`), never through the environment. `fetchr_bridge/__init__.py` calls `selftest.load()` right after installing `InProcPopen`: it imports what the bridge takes from yt-dlp, and when an installed copy fails to, drops it from `sys.path`, forgets every `yt_dlp*` module and every module loaded from that folder and imports the bundled copy, so that launch still works; the selftest then fails with that reason plus whatever else is wrong with the bundled copy. After boot `YtDlpStartup.run` calls the `selftest` bridge call (`{"ok", "version", "reason"}`: no dropped update, `yt_dlp` and `yt_dlp_ejs` from one folder and from `fetchr_ytdlp_dir` when set, `yt_dlp.utils.Popen` is `InProcPopen` and `get_exe_version('ffmpeg', args=['-version'])` answers, the JS provider registered and available on a real `YoutubeIE`) and `recordLaunch` marks the attempt good, or bad when it failed, ran another version or Python never started; an `attempt` still set at the next choice (a crash or kill before the verdict) is bad too, except that a good version is demoted only after two such launches in a row (`strikes`; a pass resets them). Bad versions are never chosen, never downloaded again or reported as installed (`update` returns the running version), and `launchChoice` deletes their files before boot; `last` keeps the latest verdict and reason, also in os_log (category `ytdlp`: `Launching yt-dlp …`, `… is skipped: …`, `passed its selftest`, `launch failed: …`; category `python`: `… from <folder> selftest took N ms`). Then, as on Android, a due daily check (auto-update on, 24 h) runs `update(running:)`; not when Python never started. `ytDlpStatus` waits up to 5 s for that startup work. Under `FETCHR_TESTING=1` (the Test action) the app runs the bundled copy, writes no record and never checks for updates.
- **Dart on iOS (`PlatformTraits`):** a plain Equatable in `lib/core/platform/platform_traits.dart`, `PlatformTraits.of(defaultTargetPlatform)` through `platformTraitsProvider` (`lib/app/di/core_providers.dart`, in the smoke test `_graph`); everything outside `app/di` and `app/bootstrap` imports it from `lib/app/shared/platform_traits_provider.dart`, a re-export, because G-app keeps views out of `app/di`. iOS is `PlatformTraits.ios`, anything else `PlatformTraits.android`, which keeps Android's UI and copy as they were. The traits, with iOS's value:
  - `supportsAria2c` false: Settings hides "Faster downloads (aria2c)" and `HomeNotifier` sends `useAria2c: false` whatever was saved.
  - `galleryWord` "Files" (Android "Gallery") and `deviceWord` "device" (Android "phone"; Dart cannot tell an iPhone from an iPad without a native call, and the window size is not the idiom): the delete dialogs ("removed from your device and from Files"), the Library empty state, the convert tile ("Pick any video on your device") and `siteOf`'s "This device" for a converted video. Core takes them as parameters (`confirmDeleteFile`, `siteOf`, `sourceLine`), because core reads no provider.
  - `updateNeedsRestart` true: when `updateYtDlp` returns a version other than the running one, `YtDlpNotifier` keeps the running status and sets `YtDlpState.pendingVersion`, which stays through a failed Check again (that version is installed and runs next launch) until the provider rebuilds. The yt-dlp card then says "Updated to X — restart Fetchr to use it" with no Up to date badge, and Home shows that line in a snackbar instead of refetching the link, which would fail again on the yt-dlp still running. The running version back is the usual up to date.
  - `asksStoragePermission` false, and `asksNotificationPermission` false for now: iOS shows its notification prompt once per install and nothing posts a notification before M6, which turns it on. So `AppInitializer` asks for nothing on iOS.
  - `readsClipboardOnResume` false: reading the pasteboard raises iOS's paste prompt, so Home reads it only on the Paste tap.

  A new platform difference is a trait, not a `defaultTargetPlatform` test, and a test pins both platforms by overriding `platformTraitsProvider` (the `platform traits keep Android's copy` and `iOS traits` groups). `systemBarsStyle` also sets `statusBarBrightness`, the one iOS reads and Android ignores.
- **Video to MP3 (`Library/VideoPicker.swift`, `Downloads/LocalVideo.swift`):** `pickVideo` shows `PHPickerViewController` (videos only, one, the original representation; it runs out of process and needs no photo-library permission). It returns nil when the user cancels or swipes the sheet down, and when the presenter is busy (already presenting, being dismissed or off screen, where UIKit would drop the present). A load error is logged by its domain and code only. The chosen file is copied to `Application Support/picked/<uuid>/<safe name>.<ext>` (the folder is excluded from backup), so the MP3 is named after the video. `convertToMp3` accepts a uri through `LocalVideo.source`, which has two boundaries: `Paths.pickedFile` (a second boundary beside `documentFile`, so a picked uri can never reach a library delete or share) or `documentFile` restricted to the media roots (`Movies`, `Music`, `Pictures`); anything else is `invalid_url`, and a missing file `unavailable`. Each attempt first runs the MP3 cut-short cleanup, then `stage` copies the source into the task dir under the name yt-dlp would save it as, and yt-dlp only converts it (`RequestBuilder.convertArgv`, Android's `convert`). The picked copy stays while its task is paused, failed or cancelled, and while another task still to finish converts the same copy; it is deleted when its task completes or is removed (`discardPicked`), and at launch any picked entry no unfinished task uses is swept. A library file used as a source is never deleted. A stored task's source goes through `LocalVideo.resolve`, which finds it again after the app container moved (a reinstall or an update changes its UUID) and checks it again.
- **Share extension (`ios/ShareExtension/`, target `ShareExtension`, id `com.defo.fetchr.ShareExtension`):** shows Fetchr in the share sheet for one web URL or text. `ShareViewController` writes the first `http(s)` URL (else the text, from which Dart's `firstUrl` picks the link) as receive_sharing_intent's JSON (`[{"path", "type": "url"|"text"}]`) into the App Group `group.com.defo.fetchr`'s `UserDefaults` under `ShareKey`, then opens `ShareMedia-com.defo.fetchr:share` through the host `UIApplication` found up the responder chain; the plugin's host side reads it and Home's `_onShared` fetches the formats. The plugin's own `RSIShareViewController` is not linked, because it would bring Flutter into the extension. `configure_xcode.rb` (`share_extension`) owns the target: sources, `Info.plist`, both targets' entitlements (`CUSTOM_GROUP_ID`), `Flutter/ShareExtension.xcconfig` (Flutter's version numbers and the signing team, never the Pods settings) and the "Embed Foundation Extensions" phase before Thin Binary. A device build needs the App Group on the developer account (automatic signing registers it). Shared files (videos) are not accepted; if they ever are, copy them into `pickedDir` first so convert keeps its two URI boundaries.
- **Library (`ios/Runner/Fetchr/Library/`):** `Library` lists `Documents/Movies/<folder>` and `Documents/Music/<folder>` with their playlist subfolders, newest first (creation date), as Android's MediaStore query does: files the user dropped in through the Files app are listed, covers in `Pictures/` never are, nor hidden files, `*.part`, `*.ytdl`, `*.temp.*` or anything `UTType` does not call a movie or audio type (`mkv` is added by hand; `webm` and `flv` list, with no duration, size or thumbnail, because AVFoundation cannot read them). The walk runs detached; duration and dimensions come from `AVURLAsset` and are cached in `Library/Caches/library-info.json`, keyed by the path relative to Documents and the modification time, so a file replaced in Files is read again. `uri` is the file's `file://` URL. **Every uri Dart sends back** (library items, a download's `savedUri`) goes through `Paths.documentFile(fromUri:)` / `documentRelativePath`, except a `convertToMp3` source, which may also be a picked copy (see Video to MP3), which decodes it fully, resolves `..` and symlinks and throws `invalid_url` unless the file is inside Documents; nothing is read, thumbnailed, shared or deleted before that. `deleteFromLibrary` deletes only a regular file under `Movies`, `Music` or `Pictures` (anything else in Documents is the user's own: `invalid_url`), counts a file already gone as deleted, prunes its playlist folder once empty but never `<root>/<folder>`, runs on the download actor so it cannot race a save, drops the completed task that saved it (`forgetSaved`) and returns true (iOS has no consent dialog). `thumbnail` (detached, utility priority) is a JPEG at quality 0.85 in `Library/Caches/thumbs/<sha256(relPath|mtime|WxH)>.jpg`, written to a temp name and renamed: audio uses only its embedded artwork (QuickLook draws a placeholder for a plain MP3), video uses QuickLook, else `Thumbnails.frame` (`AVAssetImageGenerator` at 10 % of the duration); nil when there is no picture. Neither cache is evicted (iOS clears Caches under pressure). `freeSpaceBytes` is `volumeAvailableCapacityForImportantUsage` of Documents. `share` (`UIActivityViewController`) and `openFile` (`QLPreviewController`, which Dart never calls) check the uri, return at once and present from the key window's top view controller on the main actor; on iPad the popover sits at the view's centre with no arrow. `openFolder` opens `shareddocuments://<percent-encoded folder path>/`, which shows the Files app at that folder (iOS cannot select the file), and throws `no_folder_app` when the folder is gone or `UIApplication.open` returns false. The media roots are excluded from backup whenever a save creates or reuses them. Unlike Android, `openFolder` still opens the folder when the file is gone, as long as the folder exists; folder links percent-encode everything but unreserved path characters (`;` included).

## Theming and rebrand

`lib/core/theme/app_colors.dart` is the rebrand file. Change `AppColors.seed` and light, dark, tokens and every widget follow. `error` stays red for any brand.

- `AppColors.lightScheme` / `darkScheme` are `ColorScheme.fromSeed`. `AppTokens` (a `ThemeExtension`) derives every role (`background`, `surface`, `card`, `panel`, `sheet`, `divider`, `border`, `hint`, `textPrimary`, `textSecondary`, `success`, `warning`, `errorTint`) from the scheme.
- Read colours through `context.tokens`, `context.colors`, `context.text`, `context.isDark` (`theme_extensions.dart`). **Never branch on brightness by hand** (`isDark ? a : b`) at a call site.
- A new colour role is a field on `AppTokens` (constructor, `fromScheme`, `copyWith`, `lerp`), not a one-off colour in a widget. One accent per status; do not re-derive shades per widget.
- **`const` freezes colours.** A `const` node whose colour comes from the theme will not flip between light and dark; drop `const` there.
- `Card` paints `colorScheme.surface` plus an elevation tint in Material 3; `AppTheme` pins cards with `CardThemeData(color: tokens.card, surfaceTintColor: Colors.transparent)`. Do not repaint a card's surface inside a `Card`.
- Dark mode is `themeModeProvider` (a `Notifier<ThemeMode>`, persisted under `StorageKeys.themeMode` and loaded in `AppInitializer` before the first frame); `ThemeModeButton` cycles system, light, dark.
- Rebranding does not touch the launcher icon, the native splash or the app name. The icon and the splash are Android resources in `android/app/src/main/res`, vectors only (minSdk 26 needs no PNGs and no `flutter_launcher_icons` / `flutter_native_splash`):
  - **Icon:** the adaptive `mipmap-anydpi-v26/ic_launcher.xml`, a `ic_launcher_background` colour under `drawable/ic_launcher_foreground.xml`, which is also the monochrome layer for Android 13 themed icons. Keep the glyph inside the 66 dp safe zone of the 108 dp canvas.
  - **Splash:** `drawable/splash_icon.xml`, the Home header logo tile at 4x on a 288 dp canvas, kept inside the 192 dp circle Android 12+ masks it to. `LaunchTheme` shows it through `windowBackground` (`drawable/launch_background.xml`, Android 8 to 11; transparent system bars so it centres like the edge-to-edge Flutter window). Android 12+ plays `drawable/splash_icon_animated.xml` instead: the arrow drops into the tile and the tray draws out, 800 ms, which `windowSplashScreenAnimationDuration` must equal; its first frame is the declared vector and its last frame must equal `splash_icon.xml`. Never set `windowSplashScreenIconBackgroundColor`: it shrinks the tile. The colours are in `values/colors.xml` and `values-night/colors.xml`; `test/app/launch/launch_splash_colors_test.dart` keeps them equal to `launchSplashColors`.
  - **Launch intro:** `LaunchIntro` (`lib/app/launch/`, wired by `App.splashGone` from `bootstrap`) draws the splash's last frame, a 120 logical px tile in the centre in the system brightness's colours, waits for `awaitLaunchSplash`, fades in the tagline "Any link. Any format." word by word under it, then flies the tile onto the Home header tile (`LaunchLogoTarget` in `app/shared` hands it the key) while the colours become the in-app theme, then fades. The first touch jumps to that closing fade with the tile already on the header, and is absorbed; a link shared into the app ends the intro at once (`LaunchLogoTarget.skipIntroOf`), and a launch on a route of its own (a notification's deep link) has none. Reduce motion skips the flight; with no header on screen the tile fades. Tests pump `App` or `MaterialApp` without `splashGone`, so they never see it.
  - **Glyph copies:** `assets/icons/logo.svg`, `drawable/ic_stat_fetchr.xml`, `ic_launcher_foreground.xml`, `splash_icon.xml` and `splash_icon_animated.xml` draw the same path; a new logo changes all five, plus `tool/ios/render_icons.swift`, which draws the iOS app icon (`AppIcon.appiconset`, one opaque 1024 px square: lime with the ink glyph at the adaptive icon's share) and the launch screen (`LaunchScreen.storyboard`: the `LaunchBackground` colour with the 120 pt `LaunchTile`, ink on light and lime on dark, the same tile `LaunchIntro` paints first, so the hand-off does not move) into `ios/Runner/Assets.xcassets`; run it with `swift tool/ios/render_icons.swift` and commit the PNGs. iOS caches launch screens: delete and reinstall the app to see a new one.
  - **Name:** `android:label` in `AndroidManifest.xml`, `CFBundleDisplayName` in `ios/Runner/Info.plist` and `Environment.appName`.

A loading skeleton is the real layout over placeholder data inside skeletonizer's `Skeletonizer` (the format sheet does this), with `ShimmerEffect(baseColor: tokens.surfaceSunken, highlightColor: tokens.shimmer)`, and `SolidColorEffect` under reduce motion, which the package does not read. Shared widgets live in `core/widgets` (`AppText`, `AppButton`, `AppBackButton`, `AppBackHeader` (the back arrow with a label) in `app_back_button.dart`, `AppIconButton`, `AppTextField`, `LoadingView`, `ErrorView`, `EmptyView`, `NotFoundView`, `AppSnackbar`, `SheetDragHandle`, `AudioTile` in `media_thumb.dart`, `confirmDeleteFile` in `confirm_dialog.dart`, `runUndoableDelete` in `undoable_delete.dart`); use them before hand-rolling. `AppSnackbar.showUndo(context, message)` shows a five-second Undo snackbar and resolves true only when Undo is tapped. `runUndoableDelete` hides the item, shows that snackbar, and when it closes any other way runs `commit`; a `false` or an `Err` restores the item, and an `Err` shows its message. It reads the root navigator's context before `hide()` because hiding usually unmounts the caller's tile. Bottom sheets go through `showAppBottomSheet` (`core/utils/widget_utils.dart`), never `showModalBottomSheet` directly.

## Motion

`lib/core/theme/app_motion.dart` (exported from `theme.dart`) holds the tokens, on Material 3's `Durations` and `Easing`. Use them instead of a literal `Duration(milliseconds: ...)` in any file you touch.

| Token | Value | For |
| --- | --- | --- |
| `Motion.press` | 100 ms | a finger going down (press scale) |
| `Motion.fast` | 150 ms | a finger coming up, icon swaps, a status line, a colour |
| `Motion.base` | 200 ms | content swaps, a first frame |
| `Motion.medium` | 250 ms | reveals, an overlay hiding |
| `Motion.emphasis` | 300 ms | larger moves |
| `Motion.spinnerDelay` | 200 ms | how long work runs before a spinner is worth showing |
| `Motion.standard`, `enter`, `exit` | `Easing.standard`, `emphasizedDecelerate`, `emphasizedAccelerate` | most moves, things arriving, things leaving |
| `Motion.pop` | `Curves.easeOutBack` | badges and checks only, never a layout |

`MotionSpec(duration, curve, {reverseDuration, reverseCurve})` pairs an entry with its exit; `Motion.fade` (fast, standard), `Motion.swap` (base, enter; out fast, exit) and `Motion.reveal` (medium, enter; out base, exit). An exit is shorter than its entry.

- **Reduce motion.** Read durations through `context.motion(d)` or `context.motionOf(spec)`, which are zero under Android's "Remove animations". Everything then reaches its final state on the next frame; functional timing (the 3 s player hide, the 5 s Undo window) stays.
- **Primitives in `core/widgets`:** `AppFadeSwitcher` cross-fades children keyed by the *kind* of state (`ValueKey(isLoading)`, `'paused'`), never by data that changes every tick, and its outgoing child takes no taps, focus or semantics. `AppReveal(visible:)` grows, fades and lifts a child in and out on one controller and keeps the last child so the exit plays; the leaving child takes no taps, focus or semantics. `AppPressable` is a ripple plus a press scale (none under reduce motion); `inkAbove` paints the ripple over an opaque picture, with `foreground` for the buttons that sit on it. `AppAnimatedSliverList<K>(keys:, itemBuilder:)` is a `SliverAnimatedList` that diffs the keys between builds: a new key grows, fades and rises 8 dp in (300 ms, enter), a gone one folds and fades where it was (200 ms, exit), a moved one is both and one that comes back (Undo) grows back; the first build and rows that scroll in later do not animate, rows keep their state while others come and go, and a leaving row is the last widget built for its key, inert. Give each group heading a key of its own so it comes and goes with its rows, put the gap inside the row so it folds with it, and key a row that changes group by group and id.
- **Tabs** fade through in `AppBranchSwitcher` (`app/shell/`): the old tab fades out over 90 ms (exit), then the new one fades in from 98% over 160 ms (enter), and the Style 8 pill moves on the same 250 ms, standard. Like the indexed stack it replaces, only the current tab has `TickerMode`, `HeroMode`, focus and taps (so a tap during the fade goes to the new tab, and Library still reloads as its tickers turn on), and a fully hidden tab is offstage. A tap on the open tab (bar or rail) scrolls the page's primary scroll view to the top through `TabScroll` (300 ms, standard; from more than 1.5 screens down it jumps that close first; a jump under reduce motion): a tab's main list must leave its `controller` and `primary` unset so it picks that controller up.
- **Downloads.** A task that leaves Active as completed holds its card for `savedHold` (400 ms) with a full bar and "Saved" (`DownloadCard.saved`, no taps), on an `AnimationController`, not a Timer; then the card folds away and its Done row arrives, its check popping once from 60% (320 ms, `Motion.pop`) for an id the list had not shown before, only in the frame it arrives. No hold under reduce motion or while the tab is hidden.
- **Routes** use `AppPageTransitions.theme` (`core/theme/app_page_transitions.dart`): the platform's transition (Android's predictive back one) wrapped so it is instant, with no duration, under reduce motion. `android:enableOnBackInvokedCallback="true"` in the manifest makes back go through `OnBackInvokedCallback` from Android 13; only Android 14 and later send the swipe's progress (Flutter registers an `OnBackAnimationCallback` from API 34), so the peek needs Android 14+, and on 14 the developer option. Both need the route to be a `MaterialPage` (see the router above).
- **Loading** goes through `LoadingView`, which waits `Motion.spinnerDelay` before its spinner fades in; a screen's loading, content, empty and error states cross-fade in an `AppFadeSwitcher` keyed by kind.
- **Reduce motion speeds up a plain `AnimationController` 20 times** (`AnimationBehavior.normal`). Motion widgets set their durations to zero through `context.motion`/`motionOf` anyway; a controller that measures time (a wait, a hold) passes `animationBehavior: AnimationBehavior.preserve`, or uses a `Timer`.
- **Haptics** go through `AppHaptics` (`core/utils/haptics.dart`), only for what the user did: `select()` for a choice (a pill, a filter, a quality, Undo, a seek), `confirm()` when a download or conversion is accepted, `warn()` for a cancel, delete or stop, `reject()` only inside `AppSnackbar.showFailure`. A long press gets its feedback from `InkWell(enableFeedback: true)`. Never on progress ticks, the downloads stream, scrolling, a background completion or a tab switch. The notification haptics play nothing below API 30, so `confirm` and `reject` fall back to impacts there. Tests record them with `recordHaptics` (`test/support/haptics.dart`).
- **Performance.** Animate opacity and transform through the `*Transition` and `Animated*` widgets; never put `AnimatedSize` or an entrance animation in `initState` of a lazy-list row or of a row that updates every 250 ms; a new repeating controller stops under reduce motion and comes from a `TickerProvider`, so `TickerMode` mutes it offscreen. The progress bar tweens linearly over the measured gap between updates (150 to 1200 ms) behind a `RepaintBoundary`.
- **Tests.** An animation started in a frame takes its first tick on the next one, and is done only once more than its duration has passed: after a change, pump twice, then the duration plus a millisecond (`pumpRowGone` in the downloads harness). A tab switch leaves the old tab onstage until its fade ends, so a finder can see both meanwhile.

## Environment

This app has no flavors: one app id and one display name. There is no `flavorizr.yaml` and no flavor Gradle or Xcode config, so commands run without `--flavor`. `Environment.current` (`lib/core/config/environment.dart`) always returns `prod`; set the app name there. Every environment-dependent value reads `Environment.current` or `ApiConstants.baseUrl`, so adding flavors later changes no call site. Fetchr has no backend: `DioClient` and `ApiConstants.baseUrl` are scaffold leftovers that no module calls, and every download goes through the native layer.

## Crash reporting and Sentry

`CrashReporting` (`core/crash/`) logs every error through `AppLogger` and then fans it out to every registered `CrashReporter` (today only `SentryReporter`). `bootstrap()` hooks `FlutterError.onError` and `PlatformDispatcher.instance.onError` to `CrashReporting.recordUncaught`, which skips reporters whose `capturesUncaught` is true so Sentry does not report twice. Errors thrown inside providers never reach those hooks; `ProviderErrorObserver` forwards the non-`Failure` ones to `CrashReporting.recordError`.

Sentry is on for every build, debug included: the DSN is set in `SentryFlutter.init` in `lib/app/bootstrap/bootstrap.dart`. A DSN ships inside the app binary anyway, so committing it is fine; it only lets someone send events to the project. The environment tag is `prod`.

## Pitfalls

- **`ref.watch` in `build`, `ref.read` in callbacks.** A `Notifier` reads its dependencies through `ref` inside `build()` and its methods, and never keeps them in a field assigned in `build()`, which runs again when a watched provider changes.
- **Check `ref.mounted` after an `await`** before writing `state`; the provider may have been disposed or rebuilt meanwhile.
- **An `AsyncValue` can hold a value and be loading or failed at once.** A refresh keeps the previous value, so switch on `AsyncData`, `AsyncError` and test `isLoading` instead of assuming one state excludes the others.
- **Riverpod retries failed providers by default** (ten times with backoff, for anything that is not an `Error`, a `Failure` included). Pass `retry: (_, _) => null` where a Retry button is the intended path, or the screen and the tests sit on loading.
- **An `autoDispose` provider needs a listener.** In a plain `ProviderContainer` test, `container.listen(provider, (_, _) {})` keeps it alive between reads.
- **Declare providers at top level as `final xProvider = Provider...`** in `lib/app/di/` or `lib/modules/*/di/`; the smoke test finds them by that line.
- **Never navigate before the router exists.** `routerProvider` builds the one router and `AppRouter.create()` builds a fresh one for a test. `context.go` replaces the stack, `context.push` adds to it.
- **`.w/.h/.sp/.r` only work below `ScreenUtilInit`.** Not in `main()`, not in eagerly evaluated theme constants. Themes are built lazily (`AppTheme.light()`) for exactly this reason.
- **Route parameters and `extra` can be missing.** Null-guard `state.extra` and parse path parameters defensively before casting.
- **Reset loading flags in `finally`**, not in both the success and the catch path; early returns and rethrows skip the latter.
- **The global `builder` unfocuses on tap and clamps text scaling at 1.3.** A screen that must keep focus on tap (a chat composer) handles it locally; do not remove the global builder.
- **`compute()` converters** (`isIsolate: true` on `makeRequest`) must be top-level or static functions, or capture only sendable values.
- **One `Dio`.** It is a lazy singleton built by `buildDio`; do not construct a `Dio` per request.
- **Equality must see `code`.** `Failure.props` includes it; keep it that way in new subclasses.
- **A doubled slash in an import URI** (`package:grabby//x.dart`) loads a second copy of the library; `tool/check.sh` rejects it.
- **Spell names right.** A typo in a folder or route is baked into every import forever.
- **Generated files are committed** (`*.gen.dart`, `*.g.dart`, `*.g.kt`, `*.g.swift`); `check.sh full` fails when the `build_runner` ones drift from what the generator produces. It does not check the pigeon outputs: rerun the pigeon command after a schema change.
